# 获得金钱时的钱 UI 动效设计

## 目标

每次玩家获得金钱时，让 `Canvas/CoinLabel` 整体播放一次清晰、流畅的缩放回弹动效。动效覆盖绿色钞票图标、底框和金额数字，不改变现有金额计算规则。

## 行为

- 只有金额增加时播放动效，消费金钱时不播放。
- 整个 `CoinLabel` 从编辑器配置的原始缩放快速放大到约 `1.12` 倍，再回弹到原始缩放。
- 动画播放期间再次获得金钱时，不停止、不复位当前动画，只记录一次待播放状态。
- 当前回弹自然结束后，如果期间有新奖励，则立即开始下一次回弹，形成稳定、连续的节奏。
- 多个高频触发合并为一个待播放状态，避免积累很长的动画队列。
- 森林区和玉米区使用同一套动效入口和参数。

## 结构

新增一个只负责钱 UI 表现的组件，挂载或运行时绑定到 `Canvas/CoinLabel`：

- 记录节点原始缩放。
- 提供公开的“播放获得金钱动效”方法。
- 管理自身创建的 Tween 和一个待播放状态。
- 节点禁用或销毁时恢复原始缩放。

现有森林区和玉米区的金币收集逻辑在成功增加金额后调用该统一入口。金额数据仍由原脚本更新，动效组件不持有、不修改金额。

## 数据流

1. 玩家成功获得一笔金钱。
2. 原金币收集脚本更新 `coinAmount` 文本。
3. 原金币收集脚本调用统一的钱 UI 动效入口。
4. 如果当前没有播放动画，`CoinLabel` 整体放大并回弹。
5. 如果当前正在播放动画，只记录一次待播放状态，不改变当前缩放。
6. 当前动画结束时，有待播放状态就立即播放下一次，否则保持原始缩放。

## 异常处理

- 找不到 `Canvas/CoinLabel` 时，只跳过动效，不影响加钱。
- 找不到动效组件时，可在 `CoinLabel` 上安全创建一次，避免依赖场景手工配置。
- 节点无效或已销毁时不启动 Tween，并清除待播放状态。

## 验证

- 森林区拾取金钱后，金额正确增加，整个钱 UI 播放一次动效。
- 玉米区拾取金钱后，金额正确增加，播放相同动效。
- 连续快速拾取时动效以稳定节奏持续反馈，不发生硬复位、缩放累积、无限排队或停在错误尺寸。
- 在解锁点扣钱时不播放获得金钱动效。
- 网页 Release 构建中不依赖压缩后可能变化的类名。

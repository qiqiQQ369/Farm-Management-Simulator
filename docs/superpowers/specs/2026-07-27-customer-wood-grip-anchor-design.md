# 顾客木头握持端挂点修复设计

## 问题

顾客购买木头后，替换模型会通过 `Bip001 L Hand` 与 `Bip001 R Hand`
创建动画 Socket。当前代码虽然能读取 `NaHeZi` 动作中的双手位置，却把整捆
木头的包围盒中心对齐双手中点，导致双手抓在木头中部，木头从手部两侧同时
伸出。

## 目标

- 木头圆形截面端作为整捆木头的握持端。
- 握持端对齐 `idle2_NaHeZi` 和 `walk_NaHeZi` 动作中的双手中点。
- 整捆木头只从双手位置向外延伸，最底部不再越过双手。
- 男女顾客及五套贴图使用同一套稳定规则。
- 不修改顾客购买、需求提示、金币奖励、容量、堆叠数量和离场逻辑。

## 设计

`CustomerAppearanceRandomizer` 继续使用模型中的真实左右手骨骼并创建
SkeletalAnimation Socket。顾客原有 `StoragePoint` 仍是购买产物的容器。

资源侧不再以整捆包围盒中心作为挂点，而是使用明确的 `CarryGrip` 语义：
读取已生成木头整体的握持端位置，将该握持端与左右手 Socket 中点重合。
握持端沿木头长度方向选择圆形截面一端，不使用任意固定世界坐标偏移。

位置更新只负责视觉挂载。`NPCScheduler` 调用
`ResourceManager.MoveResource(..., type 4, Vec3.ZERO)` 的流程保持不变，
`StoragePoint` 的容量和堆叠参数也保持不变。

## 稳定性

- 没有木头时不调整 `StoragePoint`。
- 任一手部 Socket、顾客节点或存放节点失效时跳过本帧更新。
- 动作切换和顾客转向后，握持端继续随真实手部骨骼更新。
- 不改变木头旋转、缩放或资源转移状态。

## 验证

- 回归测试必须拒绝“整捆中心对齐双手”的旧实现。
- 回归测试必须确认使用握持端对齐双手。
- 原有五套顾客外观、购买链路、木头和玉米顾客测试继续通过。
- `git diff --check` 通过。
